# Chess.com 분석 방식 비교와 구현 범위

확인일: 2026-10-20. 공개 기준은 공식 문서로, 화면 동작과 실제 수별 차이는 사용자가 연 Game Review로 확인했다.

현재 구현은 아래의 ‘Lite 엔진과 독립 국면 작업 분산’ 정책을 따른다. 이전 정식판 고정 정책을 설명한 부분은 변경 이력이다.

## 공개 기준

Chess.com Classification V2는 엔진 평가와 플레이어 레이팅을 예상 승점으로 환산하고, 수를 둔 뒤 감소한 예상 승점을 분류한다.

| 분류 | 공개된 예상 승점 감소 구간 |
| --- | --- |
| Best | 0 |
| Excellent | 0~0.02 |
| Good | 0.02~0.05 |
| Inaccuracy | 0.05~0.10 |
| Mistake | 0.10~0.20 |
| Blunder | 0.20~1.00 |

Great는 결과에 결정적인 수나 유일한 좋은 수, Brilliant는 나쁜 국면에 빠지지 않는 좋은 희생, Miss는 상대 실수로 생긴 승리 기회를 살리지 못한 경우를 뜻한다. 레이팅에 따른 관대함도 설명하지만 세부 계수와 경계 판정식은 공개하지 않는다.

출처: [수 분류 공식 설명](https://support.chess.com/en/articles/8572705-how-are-moves-classified-what-is-a-blunder-or-brilliant-etc).

CAPS2 정확도는 엔진 최선과의 비교를 집계한다. 공식 문서는 실제 환산식·가중치·집계 공식을 제공하지 않는다. 이 앱의 분류 개수나 최선수 비율을 CAPS2 정확도라고 표시해서는 안 된다.

출처: [Accuracy 공식 설명](https://support.chess.com/en/articles/8708970-how-is-accuracy-in-analysis-determined).

2026-08-03 공식 설명은 서버 Game Review 엔진을 Stockfish 18 full NNUE로 소개한다. 다만 2026-10-20 실제 로그인 계정의 설정에서는 리뷰 엔진이 Torch Human, 강도가 빠른(~1초)으로 표시되었고, 별도 Analysis 엔진은 Stockfish 19 Lite였다. 문서의 시점과 실제 설정을 구분해야 한다. 리뷰 화면은 고정 탐색 깊이를 공개하지 않아 앱의 깊이 16과 동일하다고 주장하지 않는다. 엔진·환경·탐색 예산이 다르므로 공개 임계값만 맞춰도 결과가 일치하지는 않는다.

출처: [엔진 공식 설명](https://support.chess.com/en/articles/9462780-how-do-the-chess-engines-on-chess-com-work).

## 화면에서 직접 확인한 동작

2026-10-20 로그인된 Chess.com에서 사용자가 연 대국을 Game Review로 분석해 확인했다. 개인 기보와 화면 캡처는 이 문서에 저장하지 않는다.

- 일반 Analysis는 탐색 깊이가 증가하는 동안 후보 수와 점수를 갱신했다. 당시 실제 로컬 분석 화면에는 Stockfish 19 Lite가 표시되었다. 위 공식 엔진 문서의 2026-08-03 설명과 시점이 다르므로 이를 동일 버전이라고 단정하지 않는다.
- Game Review는 먼저 전체 분석 진행률을 표시한 뒤 정확도·분류 요약을 제공했다. 리뷰를 시작하면 수를 선택할 때마다 해당 수의 확정된 등급·점수·설명이 나타났다.
- 블런더를 선택하면 원래 수와 이동한 두 칸을 강조하고, 설명·최선수·다음 조작을 제공했다.
- 최선수 버튼은 원래 수 직전으로 돌아가 대안 첫 수를 보여주었다. 그 뒤에는 사용자가 누를 수 있는 재생 버튼이 나타났으며 자동으로 후속 수순이 진행되지는 않았다.
- 설명(전구) 버튼은 실전 수 뒤의 예시 분기를 열고, 이전·다음·완료 조작을 제공했다. Aronian–Anand 2013의 13...Ng4에서는 14.h3 Bh2+ 15.Kh1이라는 예시를 보여주었다. 이는 실전의 14.f4나 엔진의 최선 방어와 구분해야 한다. 원본 기보를 누르면 원래 국면으로 돌아갔다.

출처: [직접 확인한 Chess.com 분석 및 Game Review 화면](https://www.chess.com/analysis). 이는 화면 동작의 관찰이며 내부 알고리즘의 구현을 확인했다는 의미는 아니다.

## 이번 구현

- 중간 탐색 PV를 화면에 표시하지 않는다. 사용자가 선택한 국면과 기존 추천은 유지하고, 검색이 완료되면 확정 결과를 표시한다. 추천·대안·응수 보기를 누르면 해당 첫 장면을 선택하고 분석하며, 이어지는 수순 재생은 사용자가 시작한다.
- 같은 깊이에서 완료된 MultiPV 후보 묶음을 사용한다. 최선수·점수·PV를 서로 다른 iteration에서 섞지 않는다. 원래 UCI 최선수는 별도 메타데이터에 보존한다.
- 전체 검토 기본값은 정밀이다. 모든 국면에 선택한 시간과 최대 2개 후보를 적용해 탐색을 집중한다. 현재 국면 재분석과 자유 탐색은 사용자가 설정한 3·5개 후보도 지원한다. 빠른 검토는 절반 시간(최대 1.5초)을 사용하며, 완료 후 선택 국면을 몰래 정밀 결과로 교체하지 않는다.
- 수 분류는 같은 출발 국면의 최선수와 실전 수를 비교한다. 같은 깊이의 후보에 실전 수가 없으면 `searchmoves` 제한 검색으로 실전 수를 따로 확인한다. 이때 요청 깊이는 최선수 검색의 실제 완료 깊이를 넘기지 않는다. 시간 제한으로 그 깊이에 도달하지 못할 수는 있다.
- 독립적으로 분석한 수 이후 국면 점수는 그래프에 사용한다. 수의 등급과 응수 설명에는 실전 수 비교 검색의 점수와 PV를 사용한다.
- 설정·시작 국면·최선수·평가·도달 깊이가 바뀌면 기존 실전 수 비교 근거를 재사용하지 않는다. 이전 버전의 엔진 결과 캐시는 갱신하며 원본 기보는 보존한다.
- 최선의 수는 엔진 1순위 또는 같은 완료 깊이의 정확한 점수 동점 후보로 한정한다. 예상 승점 환산이 포화되거나 독립 검색 점수가 좋아졌다는 이유만으로 다른 수를 Best로 만들지 않는다. 이론·특수 분류는 별도 적용한다.
- 직접 되잡는 수나 유일한 합법 수는 후보 간 점수 차이만으로 ‘훌륭한 수’로 높이지 않는다. ‘놓친 기회’는 검증된 직전 상대 실수와 현재 수의 손실을 함께 확인하며, 승리 기회 외에 방어·회복 기회도 포함한다. 일반적인 부정확의 연속을 모두 놓친 기회로 바꾸지는 않는다.
- 전구는 좋은 수를 포함한 모든 분석 완료 수에 제공한다. 수의 실제 동작과 목적을 설명하고, 검증된 희생 수락 예시가 있으면 먼저 열며 없으면 상대 응수를 연다. 해설 상자에서 이전·다음·기보 복귀가 가능하고 후속 이동은 수동이다. 핵심 예시는 최대 6반수이며 전체 예시는 별도로 선택한다. 가정한 희생 수락은 최선 방어와 구분하고 원본 기보·점수를 덮어쓰지 않는다.
- 해설은 확인된 전술 결과 또는 놓친 목적을 먼저 설명하고, 합법적인 대안과 그 수의 구체적인 목적을 덧붙인다. 동등한 교환에서 되잡을 수 있다는 사실만으로 실수 원인을 설명하지 않는다. 한국어 문구는 직접 작성하며 Chess.com 번역을 복제하지 않는다.
- 메이트 평가도 예상 승점 변화에 포함한다. 이미 진 국면에서 메이트가 생겼다는 이유만으로 무조건 Blunder, 여전히 이기는 국면에서 메이트를 놓쳤다는 이유만으로 무조건 Miss를 부여하지 않는다.

## 재현하지 않은 부분

예상 승점의 `sigmoid(centipawns / 250)` 환산, Great 10%p 차이, Brilliant의 합법 교환·보상 확인, Miss의 직전 실수·현재 손실 조건은 앱 자체 근사이다. PGN의 Elo로 임의의 Chess.com 레이팅 계수를 만들어 적용하지 않는다. 공개되지 않은 모델을 동일하다고 주장하지 않는다.

동일한 101번 이동 대국의 Game Review 등급과 점수를 화면에서 수집하고, 앱의 전체 NNUE 엔진 결과와 비교했다. 개인 기보·참조 점수·비교표는 로컬 검증 자료로만 보관한다. 이 한 대국의 차이를 줄이려고 환산 계수나 개별 수의 등급을 맞추지 않는다. 공개 문서에서 확인하지 못한 내부 수식이나 API를 추측해 제품 계약으로 삼지 않는다.

이 표본에서 기존 3개 후보·이전 분류는 57/101, 2개 후보·새 분류는 65/101이 일치했다. Chess.com의 ‘강제’ 1수를 Best로 정규화한 수치이며, 해당 수를 제외하면 56/100에서 64/100이다. 양쪽 모두 일반 점수인 공통 75개 국면의 평균 절대 차이는 0.77폰에서 0.82폰으로 늘었다. 첫 60번 이동에서는 0.223폰에서 0.220폰으로 거의 같았으며, 후반 크게 이긴 국면의 점수 차이가 전체 평균을 주도했다. 메이트 거리 차이는 일반 점수 오차에 섞지 않는다. 등급 일치 개선이 모든 국면의 점수 개선을 의미하지 않으며, 다른 대국에서의 품질을 입증하는 수치도 아니다.

## 속도 측정

동일한 대국과 Stockfish 19 full NNUE, 깊이 16, 국면당 최대 1,200ms, 1스레드, 32MB 해시로 순차 실행했다. 기존 3개 후보 검토는 98.123초, 전체 검토 2개 후보와 실전 수의 깊이 제한을 적용한 검토는 76.910초로 약 21.6% 빨라졌다. 실제 도달 깊이 평균은 15.27에서 15.78로 증가했다. 제한 검색은 33회에서 48회로 늘었으나 전체 계산량은 줄었다. 엔진 다운로드와 브라우저 화면 갱신 시간은 이 측정에 포함하지 않는다.

Chess.com Game Review는 서버에서 실행하고 이 앱은 브라우저에서 실행하므로 같은 시간·자원을 사용한다고 볼 수 없다. 위 측정은 앱 변경 전후 비교이며 Chess.com과의 속도 배율이 아니다. [서버 분석 공식 설명](https://support.chess.com/en/articles/8646880-what-is-cloud-analysis-and-how-do-i-use-it).


## 공개 고전 대국과 전구 기능의 추가 검증

2026-10-20 현재 Game Review에서 Kasparov–Topalov 1999, Morphy의 Opera 1858, Aronian–Anand 2013, Rotlewi–Rubinstein 1907을 확인했다. 일반 Analysis의 실시간 엔진 결과를 리뷰 등급으로 사용하지 않았다. 역사적인 !! 주석도 자동 리뷰 판정으로 간주하지 않았다. 대표적으로 24.Rxd4는 현재 리뷰에서 Best이고, Kasparov 대국의 Brilliant는 25.Re7+, 30.Rxb7, 33.c3+, 36.Bf1, 37.Rd7이다.

기존 희생 검사는 상대의 PV 첫 응수가 이동한 기물을 즉시 잡고 4반수 후에도 재료 손실이 남는 경우만 보았다. 새 검사는 합법적인 포획과 되잡기를 비교하는 정적 교환 평가로 수비된 기물과 폰 희생도 확인한다. 이미 잃을 기물, 즉시 얻은 기물로 손해가 상쇄된 교환, 핀으로 불가능한 포획을 제외한다. 최선 또는 준최선이며 결과가 대등 이상이어야 한다. 다른 기물을 내주는 수와 기존 노출을 이어가는 수는 별도 수락 분기에서 보상을 확인한다.

추가 분석은 희생 후보가 있는 좋은 수에만 수행한다. 기존의 완료된 포획 후보를 재사용하거나 모든 합법적인 수락 포획을 `searchmoves`로 묶어 한 차례 분석한다. 최대 500ms, 출발 국면 완료 깊이보다 한 단계 낮은 깊이(최대 16)를 요청한다. 실제 완료 깊이가 부족하거나 PV가 불법·불완전하면 확장 판정과 전구 예시에 사용하지 않는다. 분기는 원래 수·전후 FEN·설정·포획 후보 전체에 연결하여 오래된 근거를 재사용하지 않는다. 주 평가·최선수·그래프 점수는 그대로 유지한다.

이론 수의 임의적인 첫 10수 제한을 제거했다. CC0 오프닝 자료에 등록된 전체 수순(최장 36반수)을 사용한다. 목록에 없는 수를 Chess.com의 Book 개수에 맞춰 별도로 지정하지 않는다.

참조: [Kasparov–Topalov 리뷰](https://www.chess.com/analysis/game/master/969971/review), [Opera 리뷰](https://www.chess.com/analysis/game/master/765/review), [Aronian–Anand 리뷰](https://www.chess.com/analysis/game/master/13459415/review), [Rotlewi–Rubinstein 리뷰](https://www.chess.com/analysis/game/master/9644/review).


이번 비교는 216반수 전체에서 Brilliant 예측을 검사했다. 현재 Game Review의 Brilliant 양성은 Kasparov 5개, Opera 3개, Aronian–Anand 4개, Rotlewi–Rubinstein 3개로 총 15개다. 같은 엔진 원자료로 재분류했을 때 기존 검사는 0/15, 새 검사는 15/15를 찾았고 추가 예측은 1개였다(정밀도 93.75%, 재현율 100%). 추가 예측은 Kasparov의 26.Qxd4+로, 현재 리뷰에서는 Brilliant가 아니다. 일반 등급은 모든 수에서 수집하지 않았으므로 전체 등급 일치율을 계산하지 않았다. 이 네 대국의 결과를 다른 대국의 정확도나 Chess.com과의 완전한 일치로 일반화하지 않는다.

같은 희생을 이어가는 수를 계속 Brilliant로 높이지 않도록, 다른 기물의 기존 노출을 내버려 두는 수는 연결된 직전 상대수에서 생긴 새 위협인지 확인한다. 체크가 끝나 예전 포획이 다시 합법화된 것만으로 새 희생으로 보지 않는다. 같은 완료 깊이의 대안도 새 희생 없이 강제 메이트라면 이미 이기는 증거로 본다. 개별 게임 번호·수 번호에 따른 분류 예외는 없다.

네 대국의 기존 주 분석을 재사용한 희생 분기 보강에서는 추가 엔진 검색 11회에 총 1.312초가 들었고 완료된 포획 후보 8개를 재사용했다. 보강 전체는 2.899초(엔진 첫 로드 제외)였다. 이는 저장된 결과에 대한 추가 검증 비용이며 전체 대국 분석 시간을 다시 측정한 수치는 아니다. 깊이가 부족한 한 분기는 판정 확장에 사용하지 않았다. 최선 방어와 다른 수락 예시를 별도로 분석하면서도 주 평가·최선수·PV 불변 검사를 통과했다.


## 26.Qxd4+ 추가 판정과 전구 깊이 재확인

2026-10-20 Game Review에서 Kasparov–Topalov의 26.Qxd4+를 다시 선택했다. 확정 카드는 Best, 백 기준 +1.35였고, 코치 설명은 앞선 기물을 되잡는 수라는 내용이었다. 실제 수순은 `24.Rxd4 cxd4 25.Re7+ Kb6 26.Qxd4+`다. 25.Re7+의 체크 중간수를 거친 뒤 d4의 포획자를 되잡는 경우다. 이 관찰은 Chess.com의 비공개 분류 공식을 확인했다는 뜻은 아니다.

기존 앱은 바로 직전 수의 같은 칸 포획만 되잡기로 처리했다. 따라서 26.Qxd4+를 지연된 되잡기로 알아보지 못했고, 새로 공격받은 a5 나이트를 남겨 둔 별개의 탁월수로 높였다. 수정한 규칙은 원본 기보의 합법 FEN 연쇄에서 체크 중간수와 그 대응만 거슬러 올라가, 같은 칸에 남은 상대 포획자를 되잡는지 확인한다. 이 경우 다른 기물 방치에 의존한 Brilliant 및 후보 간 점수 차이에 따른 Great 자동승격을 막는다. 이동한 기물 자체가 새로 성립시키는 희생은 별도로 유지한다. 개별 수·대국 예외와 추가 엔진 검색은 필요하지 않다. 저장된 주 분석 결과를 재사용하고 새 분류만 계산한다.

전구의 화면 길이와 엔진 탐색 깊이도 분리해서 확인했다. Aronian–Anand의 13...Ng4에서 현재 Chess.com 전구는 `14.h3 Bh2+ 15.Kh1`의 3반수 뒤 다음 버튼이 비활성화되었다. 앱의 희생 수락 예시는 첫 응수가 다른 조건부 분기이며 핵심 6반수, 저장된 전체 수순은 22반수였다. 예시 길이가 길다고 엔진 검색도 더 깊다는 뜻은 아니다. 앱은 전구 안내에 해당 설명 근거의 실제 완료 깊이를 표시한다.

공식 문서상 Game Review 서버 엔진은 Stockfish 18 full NNUE다(엔진 안내 문서 2026-08-03). Game Review 강도는 Fast/Standard 및 Diamond의 Deep/Maximum을 공개하지만, 각 단계의 숫자 깊이나 전구 전용 검색 깊이·시간·최대 예시 길이는 공개하지 않는다. 로컬 Analysis의 Unlimited 설정을 서버 리뷰나 전구의 깊이로 간주하지 않는다.

앱의 일반 전구는 기존 실전 수·대안 PV를 재사용한다. 희생 수락 보조 검색의 요청 깊이는 `min(주 분석 실제 완료 깊이−1,16)`, 새 검색은 최대 500ms다. 완료된 기존 후보를 재사용하면 그 후보의 실제 깊이를 사용한다. 주 분석을 20/24로 높여도 이 보조 검색 요청은 최대 16이므로 Chess.com과 동일한 깊이라고 주장할 수 없다. 이 확인만으로 비공개 깊이를 추정해 일괄 검색 예산을 변경하지 않는다.

## 전구 전용 심층 분석과 재생 속도

2026-10-20 전구 설명의 추가 검색을 수 평가와 분리했다. 기존 전구는 장면마다 일반 위치 분석(MultiPV 기본 3)을 다시 실행했다. 이제 완료된 설명 수순을 즉시 보여주고, 선택한 설명의 출발 국면만 MultiPV 1로 보강한다. 장면 이동과 재생에서는 엔진을 다시 실행하지 않는다. 사용자가 직접 기물을 두거나 현재 국면 재분석을 누르면 일반 위치 분석으로 전환한다.

추가 검색의 목표 깊이는 `min(26,max(18,선택 깊이+2,원본 근거의 완료 깊이+2))`다. 선택 깊이 12/16/20/24의 초기 시간 예산은 각각 800/1500/2500/4000ms다. 목표에 도달하지 못했을 때만 같은 Worker와 해시를 재사용해 0/1000/1500/2000ms를 한 차례 더 허용한다. 사용자가 지정한 시간 제한이 있으면 두 검색의 합계도 그 제한을 넘지 않는다. 실제 완료 깊이는 기기·국면·엔진에 따라 다르며 목표 깊이를 보장하지 않는다. 이미 법적으로 종료된 수순과 그에 일치하는 결과를 확인했으면 불필요한 연장을 하지 않는다.

일반 응수는 실전 수 이후, 대안은 실전 수 이전, 희생 예시는 기존에 검증한 모든 합법 수락 포획으로 제한한 국면에서 검색한다. 반복 이력을 포함한 실제 기보를 전달한다. 전체 합법 UCI 수순, 완료된 단일 후보, 점수·깊이·최선수 일치, 원본 바인딩을 검증하며 불완전·경계 점수·더 얕은 결과는 기존 근거를 대체하지 않는다. 실패한 연장은 먼저 완료한 결과를 유지하고, 취소된 작업은 적용하거나 캐시하지 않는다.

전구 캐시는 최대 64개로 제한한다. 키는 원본 기보 이력·수·평가·분기 종류·포획 제한·엔진 및 검색 설정·정책 버전을 포함하며 동일 요청의 진행 중 Promise도 공유한다. 원본 점수·등급·그래프 결과를 덮어쓰지 않는다. 보강 결과가 도착하면 이미 본 수순이 일치하는 경우 이후 수순과 설명을 자동 갱신한다. 현재 기물 위치·커서·이미 본 수·재생 타이머는 유지한다. 새 수순이 이미 본 장면부터 다르면 현재 경로의 점수·설명을 함께 유지하고, 사용자가 공통 위치로 돌아오거나 다시 열 때 심층 결과를 자동 사용한다. 별도의 적용 버튼은 제공하지 않는다. 재생은 사용자가 직접 시작한다.

해설은 새 분기 점수에 맞춰 다시 생성한다. 예를 들어 Aronian–Anand의 Ng4 수락 예시는 저장된 M11 대신 새 검색이 일반 점수를 반환하면 이전 메이트 거리 문장을 남기지 않는다. 불리한 추가 결과를 유리한 희생 보상으로 설명하지 않는다. 이미 공격받던 기물이 이번 수 때문에 새로 공격받았다는 인과 설명도 제외한다. 기본 핵심 예시는 짧게 유지하되 저장된 실제 수순에서 기물 회수·메이트 또는 체크·교환의 결론이 확인되면 최대 12반수까지 확장한다. 그 이후의 결과는 전체 수순에서 확인하도록 구분한다.

실제 Stockfish 19 full NNUE, 선택 깊이 16, 1스레드, 32MB 해시에서 공개 고전 대국의 전구 6장면을 측정했다. 같은 핵심 장면을 단계별 MultiPV 3으로 다시 분석하는 방식은 추가 계산 합계 17.42초였고, 새 전구 서비스의 실제 기보 이력을 보존한 측정은 6회 검색·합계 3.078초로 모두 실제 깊이 18에 도달했다. 재방문은 추가 검색 0회였다. 엔진 첫 다운로드·초기 로드는 제외했으며 수순 길이와 기기에 따라 달라진다. 이는 설명 전략의 표본 비교이고 전체 대국 분석 또는 Chess.com 서버와의 속도 비교가 아니다. 별도 1500ms 실험에서 한 복잡한 교환은 깊이 17에 그쳤으므로, 도달 깊이와 시간 제한 상태를 그대로 표시한다.

Chess.com의 전구 전용 숫자 깊이와 시간 예산은 공개되어 있지 않으므로 동일한 내부 모델·깊이·속도를 제공한다고 주장하지 않는다. 서버 자원과 브라우저 자원의 차이도 유지된다. 이 변경은 관찰한 빠른 장면 탐색과 필요한 분기 집중 계산을 제품에 적용한 것이다.

복잡한 Rd7 교환의 반복 검증에서는 초기 1500ms에 깊이 17, 추가 1000ms 검색으로 깊이 18을 확보한 사례도 있었다. 선택 깊이 24의 목표는 26이지만 4000+2000ms 검색으로 실제 깊이 22에 그친 사례가 있었고, 더 얕게 끝난 연장 결과로 첫 완료 결과를 덮어쓰지 않았다. 시간 예산은 엔진 검색 제한이며 초기화·메시지 처리 등을 포함한 화면 응답 시간의 상한이 아니다. 전체 회귀 테스트 255개를 통과했다. 전구를 연 상태에서 깊이 또는 엔진 설정을 바꾸면 기존 예시를 닫고 원본 수를 새 설정으로 분석한다.

## 심층 설명 자동 반영과 리뷰 엔진 고정

2026-10-20 추가 요청에 따라 ‘심층 적용’ 버튼을 제거했다. 새 수순은 시작 국면·전체 반복 이력·리뷰 대상·분기 종류·탐색 범위를 확인하고, 현재 커서까지 UCI와 실제 FEN이 일치할 때만 열린 수순의 미방문 부분에 합친다. 같은 객체와 과거 수·현재 커서·기물 위치를 유지하므로 진행 중인 이동 애니메이션과 재생 타이머를 다시 시작하지 않는다. 이미 본 수와 갈라지는 수순이나 현재 커서보다 짧은 핵심 예시는 보류하고, 현재 장면의 해설·점수도 유지한다. 이전 또는 처음으로 이동해 공통 위치에 도달하면 별도 확인 없이 합친다. 새 수·다른 기보·수동 탐색으로 전환하면 이전 작업이 적용되지 않는다.

기본 리뷰 엔진은 Stockfish 19 정식판(full NNUE)이다. 시작 및 저장 기보 열기에서도 정식판을 선택하고, 저장된 Lite 평가를 정식판 결과로 복원하지 않는다. Lite는 현재 국면과 자유 탐색에서 직접 선택할 수 있지만, 전체 대국 리뷰 또는 전구 설명을 요청하면 정식판 리뷰로 전환하고 Lite 결과를 섞지 않는다. 라이브러리의 기보 자체는 유지한다. 정식판 엔진의 최초 다운로드가 필요하며, 후속 검색은 같은 Worker와 해시를 재사용한다.

현재 위치 유지, 분기 불일치·짧은 수순의 보류, 반복 이력 불일치, 잘못된 미래 수, 재생 타이머 유지 및 기본 엔진 정책을 포함한 전체 회귀 테스트 266개를 통과했다.

## Lite 엔진과 독립 국면 작업 분산

2026-10-20 추가 요청으로 기본·전체 리뷰·전구 엔진을 Stockfish 19 Lite로 변경했다. 정식판은 현재 국면 분석·자유 탐색에서 직접 선택할 수 있다. 기본 탐색 목표는 깊이 16, 국면당 최대 1200ms이고, 전구는 깊이 18 이상을 목표로 별도 검색한다. 시간 제한이 먼저 끝나면 실제 완료 깊이는 목표보다 낮을 수 있다. Chess.com 리뷰의 비공개 탐색 정책과 동일하다고 표시하지 않는다.

여기서 동시 작업 수는 엔진 내부의 SMP 스레드 수가 아니다. 단일 스레드 Lite 엔진 Worker 여러 개에 서로 다른 국면을 한 번씩 배분한다. 모든 원본 국면의 평가가 준비된 뒤 실전 수 비교·희생 검증 작업을 나눠 실행한다. 각 수는 자기 출발 국면의 평가·깊이·설정에 결합하고, 기보 순서로 분류한다. 같은 국면을 여러 Worker가 중복 탐색하거나 서로 다른 검색의 점수와 수순을 섞지 않는다. 같은 Worker를 두 단계에서 재사용하되 작업마다 `ucinewgame`으로 탐색 캐시·이력을 초기화하고 `isready` 응답 후 시작하여, 배정 순서의 영향을 줄인다.

기본 자동 작업 수는 논리 코어 수의 40%를 내림한 값이며 최소 1개, 최대 8개다. 8코어는 3개, 16코어는 6개 작업을 사용하고 수동 선택을 저장한다. 독립 Worker는 SharedArrayBuffer나 교차 출처 격리를 요구하지 않는다. 브라우저가 시스템 전체의 실시간 여유 CPU를 측정하거나 실제 점유율 40%를 강제하는 설정은 아니다. 현재 국면과 전구는 각각 단일 Worker로 계산하며, 해시 메모리 설정은 Worker당 용량이다.

중단·기보 교체·설정 변경·페이지 이탈 시 모든 리뷰 Worker를 취소하고 종료한다. 이미 완료된 결과는 저장해 중단 후 재개할 때 건너뛴다. 원래 국면 평가와 실전 수 비교의 두 단계를 진행률로 표시하며, 사용자가 보고 있는 기물 위치는 변경하지 않는다. 이전 SMP 설정 캐시는 `review-v5`로 분리하고 원본 기보는 유지한다.

기존 ‘1스레드 대 6스레드’ 실험의 검색 지연에는 `Clear Hash` 뒤 준비 응답을 기다리지 않아 생긴 초기화 시간이 섞여 있었다. 준비 완료를 기다린 통제 실험에서는 검색 응답 시간과 UCI 보고 시간의 차이가 약 6~8ms였으므로 이를 큰 검색 종료 지연 버그로 해석하지 않는다. 엔진 내부 병렬 검색의 탐색량·깊이와, 이번 독립 국면 작업 분산의 전체 리뷰 시간을 구분한다.

동일한 공개 Aronian–Anand 2013 기보(46번 이동·47국면)를 깊이 16·1200ms·MultiPV2·Worker당 Hash32로 2회씩 측정했다. 실제 서비스의 두 단계와 작업별 초기화 비용을 포함한 평균 전체 리뷰는 1 Worker 37.532초, 6 Workers 8.314초로 이 PC에서 약 4.51배 빨랐다. 엔진 최초 네트워크 다운로드와 브라우저 렌더링은 제외했고, 별도 Worker 초기화는 평균 0.148/0.216초였다. 모든 구성에서 실제 검색 55회, 작업 초기화 93회, 각 Worker 최대 동시 검색 1개를 확인했다.

각 회의 46개 수 중 45개의 등급이 일치했다. 남은 21.h3은 시간 제한으로 출발/실전 완료 깊이가 15와 12로 달라져 최선/우수로 갈렸다. 양쪽 모두 출발/실전 깊이 16을 완료한 수는 두 반복 합계 69/69개에서 등급과 실전 평가 점수가 일치했다. 기존의 16.Be2·19.Nxf8·13...Ng4의 큰 차이는 작업별 초기화 후 해소됐고, 각 구성의 반복 간 등급은 46/46개로 같았다. 모든 PV의 합법성·리뷰 결합·원본 반복 이력 보존을 확인했다. 이는 로컬 Lite 단일 작업과의 비교이며 Chess.com 판정 일치도나 다른 기기의 속도 보장은 아니다. 시간 제한이 먼저 끝나면 작업 수와 부하에 따라 완료 깊이와 판정은 여전히 달라질 수 있다.

## 사람 친화적 추천과 목적 중심 해설

2026-10-20 Stockfish 19 Lite가 완료한 후보 중 목적을 이해하기 쉬운 수를 먼저 보여주는 추천을 추가했다. 이는 전개·캐슬링·되잡기·공격받는 기물의 대피 등 판에서 확인할 수 있는 특징을 사용하는 자체 규칙이다. Torch Human을 실행하거나 그 비공개 모델을 재현한 것이 아니며, 사람의 실제 착수 확률을 학습한 모델도 아니다. 추가 엔진 검색 없이 같은 완료 결과를 사용한다.

엔진 최선과 같은 완료 깊이의 일반 점수 후보만 대안으로 비교한다. 최선 대비 평가 감소가 25cp 이하이고 앱의 예상 승점 감소가 1%p 이하인 두 조건을 모두 만족해야 한다. 백·흑의 실제 차례를 기준으로 비교하고, 더 이해하기 쉬운 구체적 목적이 확인되는 경우에만 대안을 앞에 둔다. 둘 수 있는 수가 같더라도 불완전한 MultiPV·경계 점수·다른 깊이의 후보·중복 후보는 대안 승격에 사용하지 않는다. 메이트 점수가 있는 최선을 일반 점수 또는 다른 메이트 후보로 바꾸지 않는다.

후보의 전체 UCI 예상 수순을 실제 기보 이력에서 재생해 합법성을 검사한다. 종료된 국면 뒤의 가상 수나 잘못된 승격·반복 이력을 통과시키지 않는다. 대안 착수 직후 상대의 합법 포획과 이어지는 되잡기를 제한된 범위에서 계산해 즉시 기물 손해가 보이거나 검사를 마치지 못하면 승격하지 않는다. 이 검사는 짧은 교환 안전장치이며 장기 전술의 안전이나 승리를 보장하지 않는다. 조건을 충족하는 대안이 없으면 엔진 최선을 유지한다.

추천은 화면 표시 순서와 일반 국면의 화살표만 바꾼다. 원본 `score`·`bestmove`·후보 배열·엔진 순위·등급·그래프·저장 결과는 수정하지 않는다. 추천 카드에도 원래 엔진 순위를 남기고 최선과의 평가 차이를 표시한다. 화면에 표시한 후보와 그 국면의 전체 이력을 보관해, 백그라운드 결과가 도착한 직후 클릭하더라도 다른 후보 수순이 열리지 않게 했다. 이미 연 수순의 기물 위치나 재생 경로는 새 추천으로 바꾸지 않으며, 재생 화살표는 선택한 수순의 다음 수를 가리킨다.

해설은 이동 경로와 등급 설명의 반복을 줄이고 수의 주목적부터 말한다. 중앙 통제·전개·실제 재포획·체크와 기물 공격·폰의 지원과 비숍 전개로·열린 파일·왕과 룩의 캐슬링 배치를 구체적인 칸과 연결한다. 공격과 수비는 기하학적 공격선만으로 단정하지 않고 핀과 왕의 안전을 포함한 합법 포획·되잡기를 확인한다. 희생 여부와 보상은 기존의 검증된 리뷰 근거에 맡기며, 단순히 잡힐 수 있다는 이유로 희생이나 이득을 설명하지 않는다. 등급 판정 근거는 유지하고 추천의 목적 설명과 구분한다.

현재 Chess.com의 일반 Analysis 대신 Game Review에서 Aronian–Anand 2013의 다음 12개 수를 직접 읽었다. 아래는 표현을 복사한 문장이 아니라 관찰한 목적을 요약한 것이며, 이 특정 수에만 적용하는 예외 규칙은 추가하지 않았다.

| 확인한 수 | 리뷰에서 관찰한 설명의 핵심 |
| --- | --- |
| 4.Nc3 | d5 압박과 e4 통제 |
| 4...e6 | d5 폰 지원과 비숍 전개로 확보 |
| 5.e3 | d4·c4 지원과 다른 비숍의 길 제한이라는 교환 조건 |

| 6...dxc4 | 기물 균형을 유지하는 교환 |

관찰한 리뷰에는 포괄적인 희생 설명과 어색한 한국어도 있었다. 그 표현을 그대로 따라가기보다 구체적인 대상·목적·확인된 응수를 자연스러운 한국어로 설명하도록 반영했다. 참고: [Aronian–Anand Game Review](https://www.chess.com/analysis/game/master/13459415/review?move=6).

실제 Lite 빌드로 공개 기보와 초기 국면을 포함한 18개 국면을 깊이 16·1200ms·MultiPV3·Hash32·단일 Worker에서 검사했다. 실제 완료 깊이는 14~16이었고, 18개 모두 원본 결과 불변과 선택한 전체 수순의 합법성을 확인했다. 대안을 앞세운 경우는 2개였다. 초기 국면에서는 엔진 3순위 Nf3가 e4보다 2cp 낮았고, Aronian–Anand의 6.Bd3 뒤에서는 엔진 2순위 Be7이 dxc4보다 10cp 낮았다. 두 경우 모두 예상 승점 감소도 1%p 이하였으며, 나머지 16개는 엔진 최선을 유지했다. 이는 자체 정책의 실제 엔진 표본 검사이며 Chess.com의 추천 수 일치율이나 사람다운 수의 객관적 정확도는 아니다.

브라우저에서는 초기 국면의 Nf3가 원래 후보 인덱스 2를 유지한 채 첫 추천 카드로 표시되는 것을 확인했다. 재분석 전후 보드의 64개 칸 접근성 라벨도 같아 추천 갱신이 보고 있는 기물 배치를 바꾸지 않았다. 후보 검증·점수 방향·메이트 보존·합법 포획·설명 문맥·기존 리뷰 및 재생 회귀를 포함한 전체 테스트 319개를 통과했다.
