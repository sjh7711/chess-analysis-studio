# Chess.com 분석 방식 비교와 구현 범위

확인일: 2026-10-20. 공식 공개 문서만 비교 근거로 사용한다.

## 공개 기준

Chess.com Classification V2는 엔진 평가와 플레이어 레이팅을 예상 승점으로 환산하고, 수를 둔 뒤 감소한 예상 승점을 분류한다.

| 분류 | 공개된 예상 승점 감소 구간 |
| --- | --- |
| Best | 0 |
| Excellent | 0~0.02 |
| Good | 0.02~0.05 |
| Inaccuracy | 0.05~0.10 |
| Mistake | 0.10~0.20 |
| Blunder | 0.20~1.00 |

Great는 결과에 결정적인 수나 유일한 좋은 수, Brilliant는 나쁜 국면에 빠지지 않는 좋은 희생, Miss는 상대 실수로 생긴 승리 기회를 살리지 못한 경우를 뜻한다. 레이팅에 따른 관대함도 설명하지만 세부 계수와 경계 판정식은 공개하지 않는다.

출처: [수 분류 공식 설명](https://support.chess.com/en/articles/8572705-how-are-moves-classified-what-is-a-blunder-or-brilliant-etc).

CAPS2 정확도는 엔진 최선과의 비교를 집계한다. 공식 문서는 실제 환산식·가중치·집계 공식을 제공하지 않는다. 이 앱의 분류 개수나 최선수 비율을 CAPS2 정확도라고 표시해서는 안 된다.

출처: [Accuracy 공식 설명](https://support.chess.com/en/articles/8708970-how-is-accuracy-in-analysis-determined).

2026-08-03 공식 설명에 따르면 서버 Game Review는 Stockfish 18 full NNUE를 사용한다. 앱에 탑재된 Stockfish 19 Lite/full과 엔진·환경·탐색 예산이 다르므로 공개 임계값만 맞춰도 결과가 일치하지는 않는다.

출처: [엔진 공식 설명](https://support.chess.com/en/articles/9462780-how-do-the-chess-engines-on-chess-com-work).

## 화면에서 직접 확인한 동작

2026-10-20 로그인된 Chess.com에서 사용자가 연 대국을 Game Review로 분석해 확인했다. 개인 기보와 화면 캡처는 이 문서에 저장하지 않는다.

- 일반 Analysis는 탐색 깊이가 증가하는 동안 후보 수와 점수를 갱신했다. 당시 실제 로컬 분석 화면에는 Stockfish 19 Lite가 표시되었다. 위 공식 엔진 문서의 2026-08-03 설명과 시점이 다르므로 이를 동일 버전이라고 단정하지 않는다.
- Game Review는 먼저 전체 분석 진행률을 표시한 뒤 정확도·분류 요약을 제공했다. 리뷰를 시작하면 수를 선택할 때마다 해당 수의 확정된 등급·점수·설명이 나타났다.
- 블런더를 선택하면 원래 수와 이동한 두 칸을 강조하고, 설명·최선수·다음 조작을 제공했다.
- 최선수 버튼은 원래 수 직전으로 돌아가 대안 첫 수를 보여주었다. 그 뒤에는 사용자가 누를 수 있는 재생 버튼이 나타났으며 자동으로 후속 수순이 진행되지는 않았다.
- 설명 버튼은 실전 수 뒤의 상대 첫 응수를 보여주고, 별도 분기에 후속 수순과 이전·다음 조작을 제공했다. 원본 기보를 누르면 원래 국면으로 돌아갔다.

출처: [직접 확인한 Chess.com 분석 및 Game Review 화면](https://www.chess.com/analysis). 이는 화면 동작의 관찰이며 내부 알고리즘의 구현을 확인했다는 의미는 아니다.

## 이번 구현

- 중간 탐색 PV를 화면에 표시하지 않는다. 사용자가 선택한 국면과 기존 추천은 유지하고, 검색이 완료되면 확정 결과를 표시한다. 추천·대안·응수 보기를 누르면 해당 첫 장면을 선택하고 분석하며, 이어지는 수순 재생은 사용자가 시작한다.
- 같은 깊이에서 완료된 MultiPV 후보 묶음을 사용한다. 최선수·점수·PV를 서로 다른 iteration에서 섞지 않는다. 원래 UCI 최선수는 별도 메타데이터에 보존한다.
- 전체 검토 기본값은 정밀이다. 모든 국면에 동일한 설정을 적용한다. 빠른 검토는 사용자가 선택할 수 있고, 완료 후 선택 국면을 몰래 정밀 결과로 교체하지 않는다.
- 수 분류는 같은 출발 국면의 최선수와 실전 수를 비교한다. 같은 깊이의 후보에 실전 수가 없으면 `searchmoves` 제한 검색으로 실전 수를 따로 확인한다. 동일한 시간·요청 깊이를 사용하되 실제 도달 깊이는 달라질 수 있다.
- 독립적으로 분석한 수 이후 국면 점수는 그래프에 사용한다. 수의 등급과 응수 설명에는 실전 수 비교 검색의 점수와 PV를 사용한다.
- 설정·시작 국면·최선수·평가·도달 깊이가 바뀌면 기존 실전 수 비교 근거를 재사용하지 않는다. 이전 버전의 엔진 결과 캐시는 갱신하며 원본 기보는 보존한다.
- 최선의 수는 엔진 1순위로 한정한다. 점수 차이가 없거나 독립 검색 점수가 좋아졌다는 이유만으로 다른 수를 Best로 만들지 않는다. 이론·특수 분류는 별도 적용한다.
- 메이트 평가도 예상 승점 변화에 포함한다. 이미 진 국면에서 메이트가 생겼다는 이유만으로 무조건 Blunder, 여전히 이기는 국면에서 메이트를 놓쳤다는 이유만으로 무조건 Miss를 부여하지 않는다.

## 재현하지 않은 부분

예상 승점의 `sigmoid(centipawns / 250)` 환산, Great 10%p 차이, Brilliant의 4반수 희생 확인과 재료 2점 조건, Miss의 승리/동등 구간은 앱 자체 근사이다. PGN의 Elo로 임의의 Chess.com 레이팅 계수를 만들어 적용하지 않는다. 공개되지 않은 모델을 동일하다고 주장하지 않는다.

정확한 일치 검증을 위해서는 같은 PGN·레이팅에 대한 실제 Chess.com Game Review 결과와 엔진 설정을 나란히 비교하는 별도 기준 자료가 필요하다. 공개 문서에서 확인하지 못한 내부 수식이나 API를 추측해 제품 계약으로 삼지 않는다.
